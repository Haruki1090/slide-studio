# デザインシステム

配色を決めるとき、利用者の指定やブランド色をアレンジに落とすときに読む。

## 0. 既定の見た目

**白地・墨・副色 1 色。**表紙も白地。副色は 1 枚に 1 箇所。
これが「コンサルティングファームのような明瞭さ」の実体で、装飾で足すものは無い。

| 要素 | 既定 |
|---|---|
| 地色 | 白（表紙も） |
| 主色 | 墨（`111111`）。構造・確定実績・骨格 |
| 副色 | **題材が企業ならそのブランド色**。無ければ朱（`C8102E`） |
| 所見の囲み | 主色の実線枠。副色は使わない |
| 表の強調行 | 文字を副色の太字にするだけ。淡色面は敷かない |
| 予定・推計 | 点線・白抜き。**色は変えない** |

黒地の表紙は `editorial` テーマを明示されたときだけ。既定で黒地にしたところ
「白黒ベースを無視している」と指摘された。**地は白、黒は文字と骨格のもの。**

## 1. 二層構造

**変えてよい層と変えてはいけない層を分ける。**
アレンジ＝テーマ JSON の差し替えまたは `brand` / `overrides` による上書きであって、
レイアウトコードの改変ではない。

### 層 1：意味の割当（変えない）

役割は 3 つに固定する。増やすと凡例が読まれなくなり、強調が意味を失う。

| 役割 | 意味 | 使用量 |
|---|---|---|
| `primary` | 構造・確定実績・骨格 | 最大 |
| `secondary` | 資料の主題・変化点・結論の焦点 | **1 枚に 1 箇所。面積は本文領域の 12% 未満** |
| `muted` | 補助・過去・比較対象 | 中 |

| 要素 | 意味 |
|---|---|
| 実線 | 確定・実績 |
| 点線 | 未実施・予定・推計 |
| 矩形（角丸なし） | 事業・組織・構成要素 |
| 円 | 時点イベント |

副色を主題にだけ当てると、**資料を流し読みしたときの副色の分布がそのまま主題の分布になる。**
これが効くので、強調のために副色を使い足さない。
`check_layout.py` が副色の箇所数（部品グループ単位）を数え、2 箇所で WARN、4 箇所で ERROR を出す。

「1 箇所」の数え方：棒グラフの 1 本（値と軸ラベルを含む）、カード 1 枚、表の 1 行、
KPI 1 個、タイムラインの 1 件、所見の囲み 1 つ。**図の主題と、ペインの要点の両方に
副色を当てるのは 2 箇所。**ペイン側は主色の太字で足りる。

### 層 2：見え方（テーマファイル）

`assets/themes/*.json`。同梱は 4 つ。

| 名前 | 用途 | 表紙 |
|---|---|---|
| `default` | 白地＋墨＋朱。既定 | 白地 |
| `mono` | 完全モノクロ。印刷・保守的な提出先 | 白地 |
| `navy` | 紺基調。金融・重工・官公庁 | 白地 |
| `editorial` | 大見出し。対外発表・登壇。**指定時のみ** | 黒地 |

部分上書き：

```js
new Deck({ theme: "navy", overrides: { grid: { margin: 0.7 }, type: { sizes: { head: 20 } } } });
```

## 2. ブランド色の採取と写像

### いつ採るか

F0 の配色が「企業ブランド色」のとき（題材が企業なら既定でこれ）。F1 の調査で採る。

### どこから採るか

| 優先 | 採取元 | 見るもの |
|---|---|---|
| 1 | 公式ブランドガイド・プレスキット | 指定色（RGB / hex） |
| 2 | 企業サイトのトップ | ロゴの色、グローバルナビの地色、見出し・ボタンの色（CSS の `color` / `background`） |
| 3 | IR 資料の表紙 | 支配的な 1 色 |

**採るのは色の値だけ。ロゴ画像は貼らない。**採取元の URL を記録し、納品時の申告に書く。

4 色以上あっても**最も彩度の高い 1 色を副色に**写像し、残りは使わない。
主色は墨のままにする（ブランドの濃色を主色にしたいときだけ `brand.primary`）。

### 検査する

```bash
node scripts/brand_theme.js default 0055A4 > /tmp/brand.json     # 写像したテーマを解決
python3 scripts/check_contrast.py /tmp/brand.json                 # 可読性
```

通ったら `new Deck({ theme: "default", brand: { secondary: "0055A4", source: "<URL>" } })`。
`secondaryPale`（淡色）は自動で導く。生成後は `check_contrast.py out.manifest.json` で
実際に使った palette を再検査できる。

### 基準を割ったときの扱い

**色そのものを黙って差し替えない。使い方を変える。**

| 状態 | 対応 |
|---|---|
| 副色のコントラストが 4.5 未満（黄・水色など） | 面（塗り）では使わず、**線と文字に限定**する。棒の accent は塗りになるので、その枚は表や KPI の文字色で主題を示す |
| 採れなかった | `default` の朱で進め、採れなかった旨を申告 |
| 注記色が 3.0 未満 | 一段暗い階調に置き換えることを提案し、了承を取る |

理由を伝えたうえで運用を変えるので、利用者のブランドは保たれる。

## 3. フォント方針

既定は `shipMeiryo`。**pptx に書き込まれるのはフォント名で、実体は閲覧側が解決する。**
つまり納品 pptx は本物の Meiryo で表示される。

| 方針 | pptx | PDF | 使いどころ |
|---|---|---|---|
| `shipMeiryo`（既定） | Meiryo | 変換段 1〜2 なら一致、3 なら代替＋注記 | 通常 |
| `portable` | BIZ UDP ゴシック | 完全一致 | PDF の見た目を保証したいとき |

`portable` が成立するのは、BIZ UDP ゴシックが **Google Fonts に OFL で配布されており
（こちらにインストールできる）、かつ Windows 10 (1809) 以降に標準搭載されている
（閲覧側にもある）** ため。両側に存在しうる数少ない選択肢。

### 文字幅の扱い

**レイアウト検査はフォント実体に依存しない。**日本語の全角はどの書体でも 1em 幅なので、
文字種で分類すれば十分な精度が出る。代替フォントで描画されても検査の精度は落ちない。

測れないのは**行送り**だけ。Meiryo は行高がやや高いので、
テキスト枠には 1 割の余裕を持たせ、1 行あたりの全角文字数に上限を設ける（`layout.md`）。

## 4. 禁止事項

実装レベルで守る。定型的に見える装飾はここで潰す。

- 角丸（`rectRadius` は使わない。`RECTANGLE` のみ）
- タイトル直下の装飾ライン。**構造上の区切り線とは区別する**
  （ヘッドメッセージ下の実線とフッタ上の点線は構造。それ以外に線を引かない）
- スライド幅いっぱいのカラーバー、片側だけの縁取り、サイドラベル
- クリーム・ベージュ系の地色。黒地の本文
- 副色の淡色面を所見や表に敷く（副色の面積が膨らみ、主題がぼける）
- 役割外の色。`deck.lib.js` は役割名でしか色を受け取らないので、違反すると例外が飛ぶ
