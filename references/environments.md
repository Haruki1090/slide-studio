# 実行環境の階層

F0 で読む。

## 1. 階層

| 階層 | 環境 | 使えるもの | 検証の到達点 |
|---|---|---|---|
| **T0** | ファイル書き込みのみ | pptx 生成、静的検査 | 機械検査まで。**PDF を出せない** |
| **T1** | 一般的なサンドボックス | ＋ bash、LibreOffice、poppler、画像閲覧 | ＋ 自己目視 |
| **T2** | ローカルの Claude Code | ＋ サブエージェント、ローカルの Office / フォント | ＋ 初見レビュー、PDF が完全一致 |

## 2. 判定

```bash
bash scripts/doctor.sh
```

見るもの：`node` と `pptxgenjs`（無ければ生成そのものが不可）、`soffice` と `pdftoppm`
（無ければ T0）、日本語フォントの実体、ローカルの PowerPoint。
T2 かどうか（サブエージェントの有無）は呼び出し側が判断する。

## 3. 階層で変わるもの・変わらないもの

| 工程 | T0 | T1 | T2 |
|---|---|---|---|
| 調査 | 直列 | 直列 | 論点別に並列 |
| 形式検証・レイアウト検査 | ○ | ○ | ○ |
| PDF 出力 | **×** | ○（代替フォント） | ○（完全一致） |
| レイアウト目視 | × | 自己目視 | 初見レビュー |
| 数値主張の検算 | データ表と突合 | 画像と突合 | 独立エージェントが突合 |
| **7 原則・例外カタログ・ゲート** | 同一 | 同一 | 同一 |

最終行が重要。**品質規則は階層で変えない。**変わるのは検証の厳しさと速度だけ。

## 4. 足りないときの打開策

着手前に伝える。作ってから出せないと言うのが最悪。

| 不足 | 打開策 |
|---|---|
| pptxgenjs | `npm install pptxgenjs` |
| LibreOffice | `winget install TheDocumentFoundation.LibreOffice` / `brew install --cask libreoffice` / `apt-get install -y libreoffice` |
| pdftoppm | `apt-get install -y poppler-utils` / `brew install poppler` |
| PDF が全滅 | pptx 単体で納品し、**その旨を申告する** |

## 5. 非対話モードへの対応

パイプやフックから走ると質問しても答えが返らない。
依頼文に完了指示がある場合も実質同じ形になるので、**両方を同じ規則で吸収する。**

> 確認は G2 で 1 回だけ、まとめて行う。応答が得られない、または依頼文に完了指示がある
> 場合は、フォールバック既定（`default` テーマ／pptx + pdf／20 枚超のみ Appendix 分離）
> で進行し、**採用した既定値・検知した食い違い・作れなかった項目を成果物の冒頭に
> レポートとして出力する。**

質問できないことを理由に品質を落とさず、勝手な推測も残さない。判断を成果物側に記録する。

## 6. 規約の線

取得を拒否しているページには、T2 でブラウザ自動化が使えても回り込まない。
**これは能力の制約ではなく規約の制約なので、階層が上がっても越えない。**
