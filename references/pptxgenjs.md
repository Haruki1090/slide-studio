# pptxgenjs の地雷集

F4 で実装するときに読む。**自前で保有している。外部スキルを参照しない。**
`deck.lib.js` を使っていれば大半は踏まないが、直接触るときはここを見る。

## 1. ファイルが壊れる書き方

| やってはいけないこと | 結果 |
|---|---|
| 色コードに `#` を付ける（`"#FF0000"`） | ファイルが壊れて開けない |
| 色に透明度を混ぜた 8 桁 hex（`"00000020"`） | 同上。透明度は `transparency: 0-100` で渡す |
| `shadow.offset` に負値 | 同上。上向きの影は `angle: 270` ＋ 正の offset |
| 積み上げ棒で `dataLabelPosition: "outEnd"` | 同上 |
| `<p:presentation>` の子要素順序を入れ替える | 他ツールは通すが PowerPoint が開けない |

`scripts/validate_pptx.py` はこれらを直接検出する。

## 2. 静かに壊れる書き方

| やってはいけないこと | 結果 |
|---|---|
| `pres.layout` を設定しない | 既定 10×5.625 インチ。はみ出した図形は**黙って消える** |
| 同じ options オブジェクトを複数の `addShape` に渡す | 内部で EMU に書き換えられ、2 個目以降が崩れる |
| `rectRadius` を `RECTANGLE` に付ける | 効かない |
| `letterSpacing` | 無視される。正しくは `charSpacing` |
| `addText` に `isTextBox: true` を付けない | 支援技術が「図形」として読み上げる |
| テキスト枠の `margin` を 0 にせず図形と揃える | 内部余白のぶんだけずれる |
| 箇条書きに `•` を直接書く | 二重の中黒になる。`bullet: true` を使う |
| 1 つの `new pptxgen()` を複数ファイルに使い回す | 内容が混ざる |

## 3. グラフ

**`addChart()` は使わない。**理由は `charts.md` と `layout.md` に書いたとおり、
色の意味づけと注釈の配置を確実に通すため。棒は矩形で描く。

## 4. 実装の作法

- 色は `deck.lib.js` の役割名経由でのみ渡す。生の hex をスライド側に書かない
- 図形の options は毎回新しいオブジェクトリテラルで作る
- 座標は変数に置き、マジックナンバーを式の中に埋めない（修正時に追えなくなる）
- **出力ファイルを手で直さない。**必ず生成スクリプトを直して作り直す
