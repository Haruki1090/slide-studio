# 検証手順

F5 に入る直前に読む。

## 1. 順序

**機械で落とせるものを先に落とす。**目視は最後、かつ「機械に見えないもの」に集中する。

```bash
python3 scripts/validate_pptx.py out.pptx            # 形式（PowerPoint が拒否する破損）
python3 scripts/check_layout.py out.manifest.json    # レイアウト（描画前）
bash    scripts/render.sh out.pptx <outdir>          # PDF 4 段梯子 ＋ 画像化
```

`check_layout.py` の ERROR はすべて生成スクリプトを直して作り直す。
WARN は判断のうえ残してよいが、残す理由を持つこと。

## 2. 自動で見ているもの

| 検査 | 内容 |
|---|---|
| 出典 | フッタの出典が空でない |
| ヘッドメッセージ | 体言止めでない／論点が 2 つ以上でない（WARN） |
| はみ出し | 文字数から推定した必要高さが枠を超えていない |
| 余白 | 要素が左右の余白・ヘッドメッセージ領域・フッタを侵していない |
| 衝突 | 別グループのテキスト同士が重なっていない |
| 副色 | 塗り面積が上限内（WARN） |
| 通し番号 | ページが連番 |

## 3. 自動で見ていないもの（目視に残るもの）

- 余白の偏り、視線の流れ、密度のバランス
- グラフの表現が主張に対して適切か
- **本文の数値主張とグラフ・表の値の一致**
- 全体を通したトーンの一貫性

## 4. 画像を 2 回通す

**同じ画像でも目的が違う。混ぜると内容検査が必ず抜ける。**

### パス 1：レイアウト目視

- 文字の切れ、要素の重なり、注釈が図を覆っていないか
- 余白が偏っていないか（片側だけ空いている）
- 列やカードの揃い

### パス 2：内容の検算

**本文の数値主張を先に列挙してから、画像の値と突き合わせる。**
逆順（画像を見てから主張を思い出す）にすると、書いたつもりの内容が見えてしまう。

チェックする対象：

- ヘッドメッセージに含まれる数値・比較・方向（増えた／減った／最高）
- 「連続」「すべて」「初めて」といった全称・唯一性の主張
- 図の傾向と本文の断定が一致しているか

前回、「21 作連続で伸ばし続けており」と書いた枚で、実際には 4 作が前作割れしていた。
これはパス 2 でしか拾えない。拾ったら **F2/F3 へ回帰してヘッドメッセージを直す。
グラフ側を都合よく変えない。**

## 5. T2：サブエージェントに任せる

サブエージェントが使える環境では、パス 1 とパス 2 を独立したエージェントに渡す。
`agents/reviewer.md` の指示に従う。渡すのは 3 つだけ。

- スライド画像
- チェックリスト（**レイアウト用と内容用を別々に**）
- 本文の数値主張のリスト（**図の値は渡さない**）

生成スクリプト・設計意図・ガバニングソートは渡さない。
渡すと「そう見えるはず」の補正がかかり、初見の目という利点が消える。

## 6. 打ち切り

配置の不具合の修正は **2 周まで。**3 周目に入りそうなら、残っている不具合を
列挙して納品時に申告する。際限のない微調整は、得られる改善より消費が大きい。

事実誤認の修正に上限は無い。

## 7. 納品時の申告（必須）

1. 構成のサマリ
2. 作れなかった項目と理由
3. 推定・欠測として扱った箇所
4. **どの水準で検証したか**（PDF の変換段、目視の有無、未検証の領域）

4 を書かない成果物は、検証していない部分を検証したように見せることになる。
