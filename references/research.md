# 調査プロトコル

F1 に入る直前に読む。

## 1. 探索の形

**広いクエリで地形を掴み、出てきた固有名詞を手がかりに一次情報へ降りる。**
最初から一次情報を狙い撃つと、そもそも何が一次情報なのかが分からない。

```
広いクエリ（2〜6 語）
   ↓
結果に一次情報の URL が含まれるか
   ├ Yes → 全文を取得して数値・日付を抽出 → 採否判定（3 章）
   └ No  → 語を入れ替えて再構成（同じクエリは投げない）
              ↓
           取得できない（robots 拒否・ログイン壁）
              → 同内容を持つ別ソースへ迂回
              → 無ければその項目を落とす（推測で書かない）
```

## 2. 降り方の具体

1 本目の広いクエリで得るのは事実ではなく**手がかり**である。次の 3 つを拾う。

- 正式な組織名・法人格（決算公告や登記情報にたどり着く鍵）
- 制度上の分類（上場／非上場、認可／無認可、業種コード）
- 関係する固有名詞（親会社・レーベル・提携先・人名）

これらが揃うと、一次情報の在り処が決まる。典型的な降り先：

| 欲しいもの | 降り先 |
|---|---|
| 業績 | 有価証券報告書、決算公告（官報）、決算短信 |
| 事業構成・体制 | 企業サイトの会社概要・事業紹介・ニュースリリース |
| 市場規模 | 業界団体、調査機関の公表資料（一次の統計） |
| 人口・制度 | 官公庁の統計 |
| 実績値（動員・販売） | 当事者のプレスリリース、チャート運営元 |

## 2b. ブランド色の採取（企業が題材のとき）

F0 の配色が「企業ブランド色」なら、調査の初手で企業サイトを開いたときに**ついでに採る。**
後回しにすると忘れて `default` の朱で作ってしまう（前回の失敗）。

| 優先 | 採取元 | 見るもの |
|---|---|---|
| 1 | ブランドガイド・プレスキット | 指定の hex / RGB |
| 2 | 企業サイトのトップ | ロゴ・グローバルナビ・見出しの色（取得した HTML/CSS の `color` `background`） |
| 3 | IR 資料の表紙 | 支配的な 1 色 |

採った hex と採取元 URL を記録する。写像と検査の手順は `design-system.md` 2 章。
採れなければ `default` で進め、採れなかったことを G2 と納品時に申告する。

## 3. 情報の合格点

**「断定できるか」ではなく「どう書けば嘘にならないか」で決める。**
確度が落ちたら捨てるのではなく、書き方の強度を落とす。

| 状態 | 扱い |
|---|---|
| 一次情報で確認できる | 断定して本文に書く |
| 複数の二次情報が一致 | 断定して書き、出典を併記 |
| 三次情報のみ（百科事典・個人集計） | 裏が取れた範囲だけ使い、出典にその旨を明記 |
| 事実は確かだが因果は不明 | 並置にとどめ、**推定と明示する** |
| データが存在しない | 欠測として見せる。内挿しない |
| 出典に到達できない | **項目ごと落とす** |
| 自分の定性判断 | 判断であることを脚注で明記 |

数値が矛盾したら、新しい方・一次に近い方を採る。差が 10% を超えるなら両論併記。

## 4. 打ち切り条件

**同じクエリを二度投げない。**結果は変わらない。

- 語を替えて 2 回、切り口を替えて 2 回の**計 4 回不発で打ち切る**
- 打ち切った項目は構成から外し、外したことを G2 と納品時に申告する
- 取得コールは 1 案件あたり **25 件が上限**。超えたら劣化戦略に入る

## 5. 差分に注意を払う

**新旧 2 つのソースを突き合わせて初めて出る情報がある。**
片方にあって片方に無い事実は、たいてい重要な変化点を指している。

実例：百科事典に「施設運営事業＝劇場」とあり、企業サイトの現行の会社概要から
それが消えていた。この差分から譲渡の事実にたどり着き、資料の構成が 1 枚増えた。
単独のページを順に読むだけでは出てこない。

意識して見る差分：

- 会社概要の事業内容が、過去の記述と変わっていないか
- 役員・代表者が変わっていないか（誰が昇格したかは戦略の方向を示す）
- 事業の一覧から**消えたもの**は無いか（増えたものより情報量が多い）

## 6. 記録

調査中、次を手元に残す。G2 の提示と F6 の申告で使う。

- 採用した出典の一覧（URL・媒体名・階層）
- ブランド色の hex と採取元（採ったとき）
- 各スライドに割り当てた事実と、その出典の対応
- **打ち切った項目とその理由**
- 推定として扱うと決めた記述

## 7. この段階で起きやすい例外

`exceptions.md` の A 章（A1〜A9）を参照。特に：

- A1 一次情報が存在しない
- A4 情報が多すぎて論点が発散する（**先に仮のガバニングソートを立てて絞る**）
- A7 空振りし続ける
- A8 依頼者の前提が事実と違う
